# Disassemblies of the PC-1600 ROM dumps

Every dump in [`../dumps/`](../dumps) has an annotated disassembly here. Each one uses the
same file name with `.asm` and sits at the matching path:

```
dumps/new/PC1600-P0-B0.BIN                  ->  disasm/new/PC1600-P0-B0.asm
dumps/old/…                                 ->  disasm/old/…
dumps/ce1600p/{new,old}/PC1600-P1-B4-….BIN  ->  disasm/ce1600p/{new,old}/PC1600-P1-B4-….asm
```

All 16 sources reassemble **byte-identical** to their dumps (see
[Assembling](#assembling-back-into-bin)). Each file names its dump and that dump's MD5 in the
first lines.

- **Labels and comments.** Routines have names and header comments. System entry points
  carry the names of Sharp's documentation (TRM / Systemhandbuch). The LH5803 ROM carries
  the names of the PC-1500 A04 ROM it is based on.
- **Origin.** The files were generated by a separate annotation project. Lines such as
  "Generated by tools/romdis/… from ….ann — edit the .ann file", and references to
  `notes/…`, belong to that project; neither exists in this repository.
- **Dialects.**
  - The Z-80 banks: [`z80asm`](https://www.nongnu.org/z80asm/).
  - The LH5803 ROM: `sdas` (`sdaslh5801`).

## What the ROMs contain

### Calculator (PC-1600)

| File | Seen at | Contents |
|---|---|---|
| `PC1600-P0-B0` | 0000H–3FFFH, always mapped | RST vectors and the fixed jump table (the public API); reset / power-on, module scan, bank switching (BANKJP / BANKCAL); the core of the BASIC interpreter: number conversion, variables, expression evaluator, statement loop, errors, BASIC interrupts. |
| `PC1600-P1-B0` | 4000H–7FFFH, bank 0 | The continuation of P0-B0 (one program across 4000H): screen editor and line input, program-line storage and LIST, and the statement handlers not in bank 3 (IF, GOTO, GOSUB, FOR/NEXT, LET, DIM, CLS, CURSOR, INKEY$ …). |
| `PC1600-P1-B3` | 4000H–7FFFH, bank 3 (port 3DH b2 = 1) | Called like a ROM module. Holds the IM2 interrupt dispatcher, LCD character output, the keyboard scan, the RAM-disk file system (S1: / S2:), the COM: file driver, the switch to the LH5803 (PC-1500 mode), CALL/OUT/POKE, the memory map, POWER, WAKE$, EOF/LOF/LOC/DSKF, and the kanji input for the JAPAN ROM. |
| `PC1600-P1-B3B` | 4000H–7FFFH, bank 3b (port 3DH b2 = 0) | The "hidden BASIC ROM" for keywords whose token-table bank byte is 06H. It covers program commands (CONT, AUTO, LIST, NEW, PASS, RENUM, ON …), clock and alarm, analog input, the serial-port statements, files and devices (OPEN, CLOSE, SAVE, LOAD, COPY …) and LCD graphics. |
| `PC1600-P2-B6` | 8000H–BFFFH, bank 6 | The display, keyboard, RS-232C (TC8576) and timer / sub-CPU IOCS, the BCD arithmetic, the roman-kana conversion, the 6×8 LCD font and the built-in BASIC token table. |
| `PC1600-LH5803-C000-FFFF` | LH5803 view C000H–FFFFH | The PC-1500 compatibility CPU's ROM: Sharp's PC-1500 A04 ROM adapted to the PC-1600. It adds the CALLH bridge to the Z-80 (E000H–E23CH) and built-in katakana in place of the BASIC commands the Z-80 now executes. It also patches A04 code, moves the interrupt handlers and mirrors the PC-1500 display onto the PC-1600 LCD. |

### CE-1600P (printer / plotter / cassette interface)

| File | Seen at | Contents |
|---|---|---|
| `PC1600-P1-B4-CE1600P` | 4000H–7FFFH, bank 4 | 4-colour pen plotter: module header, printer IOCS 00H–36H (PCHEK / POUT / PKOUT entries), the stepper and pen mechanics, the vector font (PLOTFONT), and the BASIC keywords COLOR, CSIZE, GRAPH, TEXT, LLINE, RLINE, LPRINT, LLIST … |
| `PC1600-P1-B5-CE1600P-OR-F` | 4000H–7FFFH, bank 5 | Two 8 KB modules. 4000H: the CE-1600F floppy driver (X: / Y:, disk IOCS, FILE functions, boot). 6000H: the cassette (CAS:; CLOAD, CSAVE, MERGE, CHAIN, RMT) through the CE-1600P. |

The CE-1600P's ROM is in the peripheral, so an OLD or NEW CE-1600P works with an OLD or NEW
calculator. Both versions reach bank 0 only through the fixed jump table.

## What changed from OLD to NEW

A high-level summary of the differences between `old/` and `new/`.

### Calculator Z-80 ROM (P0-B0, P1-B0, B3, B3b, B6)

The NEW ROM is a reworked release. Most code moved, but the public interface stayed: the
jump tables, token numbers and IOCS numbers are the same. The P0-B0 jump table gains four
entries at its end.

- **Code moved between banks:**
  - the sound IOCS: B6 → B3;
  - the reset helpers and EXCOMM1500: P0-B0 → B3;
  - the LINE statement: P1-B0 → B3b;
  - key definition / DEF-key label execution: P1-B0 → P0-B0.
- **Japanese-model features added.**
  - The WIDTH command (16-dot kanji matrix), kana voicing marks and kana punctuation keys,
    and kanji code input.
  - The kanji-function keywords and WIDTH are in the token table with their second letter
    replaced by 00H, so they cannot be typed on this ROM.
  - The JAPAN ROM is now detected by the header `M`,3xH/4xH (OLD: `D`,16H) and flagged in
    bit 0 of the module flags (OLD: bit 1).
- **Fixed:**
  - **Arrays:** the element address of a 2-D array with a first dimension of 255. The OLD
    ROM computes bound+1 in 8 bits, so the second index is lost.
  - **User interrupt hook:** the OLD ROM calls one byte before JPHLA, so an extra
    `DEC BC` runs first.
  - **LCD font:** character D7H (`╫`) lacked its horizontal stroke.
  - **COM driver:**
    - two new IOCS functions (22H stop the sender, 23H wait);
    - RTS is raised again when the receive buffer is read;
    - the status byte is updated with interrupts masked.
  - **PEEK# / POKE** with a bank number now refuse addresses in the unbanked pages.
  - **Smaller fixes:**
    - variable names are collected outside the input buffer;
    - TIME$ ON/OFF/STOP inside an expression gives an error;
    - PRINT number fitting and print zones in the one-line window;
    - the screen editor;
    - LOF;
    - PASS.
- **Leftover bytes.** The OLD images contain leftover bytes, including code of older builds,
  where the NEW ones have zero fill.

### LH5803 ROM

Only 110 bytes differ, all at the same addresses.

- **MODE 1 program bank:** the NEW ROM maps the BASIC program's bank when the Z-80 has the
  PC-1500 interpreter execute a command, and in PEEK / PEEK#. It restores the bank
  afterwards.
- **Slot check:** the OLD check before CSAVE / CLOAD / MERGE / CHAIN / LLIST, for a program
  in S1 / S2, reads the wrong slot's descriptor and tests the flag with the opposite sense.
- **Removed vectors:** the stub for vectors 5AH / 9AH / 9CH starts with the wrong byte in
  the OLD ROM (4AH instead of 04H), so these vectors run on out of step.
- **Katakana flags:** the PC-1500-mode power-on clears KATAFLAGS in the OLD ROM; the NEW one
  sets it to FFH for the built-in katakana.

### CE-1600P

- **Floppy module:** identical in both versions.
- **Cassette:**
  - CSAVE of a program spread over several banks no longer writes an empty first block.
  - MERGE also stops at the end of the loaded data.
  - A failed OPEN no longer leaves the file marked as open, which used to cause error 99H
    on the next OPEN.
- **Plotter font:** 15 characters redrawn: the underscore, the accented letters with grave,
  acute or ring (é è à å á ò ó ù ú Å), φ, ≈, ° and the kana middle dot.
- **Plotter code:**
  - flag updates are made safe against the interrupt hook;
  - printing text no longer changes the dashed-line setting;
  - the LPRINT column count is kept around POUT;
  - LLIST handles a program that starts at a bank boundary;
  - a glyph that ends with a pen move is handled;
  - printer power switching in the interrupt no longer touches the interrupt mask;
  - HARESET and the short carriage return are fixed.
- **Bank 0 calls:** the OLD version called bank 0 through its own jump vectors; the NEW one
  calls it directly.

**Easy tests on a real machine.** Two BASIC one-liners show the difference between OLD and
NEW:

- `DIM B(255,2): B(3,0)=1: B(3,2)=2: PRINT B(3,0)` prints 2 on the OLD ROM, 1 on the NEW.
- `PRINT CHR$(&D7)` shows `║` on the OLD ROM, `╫` on the NEW.

These are derived from the code and have not yet been run on hardware.

## Assembling back into .BIN

### Z-80 banks (12 files)

Assembler: **z80asm** 1.8 by Bas Wijnen, https://www.nongnu.org/z80asm/.

- **macOS:** `brew install z80asm`
- **Debian / Ubuntu:** `apt install z80asm`

```sh
z80asm -o PC1600-P0-B0.BIN new/PC1600-P0-B0.asm
```

The `org` in each source makes the output exactly the 16 KB image, with no padding or
trimming needed.

### LH5803 ROM (2 files)

Assembler and linker: **sdaslh5801**, **sdld** and **makebin** from the SDCC fork with the
LH5801 back end, https://github.com/pchambre/sdcc-pc1500. Build it as described in its
README. The tools end up in `sdcc/bin`.

```sh
sdaslh5801 -o PC1600-LH5803-C000-FFFF.asm       # -> PC1600-LH5803-C000-FFFF.rel
sdld -i PC1600-LH5803-C000-FFFF.ihx PC1600-LH5803-C000-FFFF.rel
makebin -s 65536 PC1600-LH5803-C000-FFFF.ihx full.bin
tail -c 16384 full.bin > PC1600-LH5803-C000-FFFF.BIN   # keep C000H-FFFFH
```

### Check

Compare the result with the dump (`cmp new.BIN ../dumps/new/….BIN`), or its MD5 with the
one in the source header and in the top-level [README](../README.md#verification).
